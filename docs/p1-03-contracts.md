# P1-03 — Versioned transport contracts (first verified slice)

**Normative input:** [P0 England pilot contract](p0-case-contract.md), especially P0-03. This document describes a **transport-adapter slice**, not an implemented game service or a completed P1 gate.

## Authoritative boundary

- `myth-domain` retains its pure checked Rust types and its independent simulation logic. The separate `crates/contracts` crate owns untrusted JSON decoding and conversions into those types.
- `parse_command` reads a strict Serde `CommandEnvelope`, rejects extra JSON fields, validates `schema_version == 1`, IDs, version decimals, budgets, policy caps, audit quarters and evidence recipient sets, then constructs a domain `CommandEnvelope`. **Deserializing a wire DTO alone is not admission.** The P3 reducer still decides authorization, freshness, affordability of amendments, vote eligibility, reserved funds and idempotency.
- `parse_minister_action` consumes a strict, **stage-specific** `MinisterAction`: first-stage input requires `counterproposal_source` and forbids private effort; final-stage input forbids `counterproposal_source` and permits a role-scoped optional effort field (required for Education/Infrastructure, omitted for Finance). When supplied, effort must be a bounded integer; an explicit JSON `null` is rejected. It checks role restrictions, validates typed conditions, and mechanically assesses the allocation against available credits. It returns a **public** `FirstPosition` or `FinalPosition`, plus a separate **private** effort declaration. The raw minister input deliberately does **not** implement serialization, and must never be sent to a public view.
- `PublicRoleView` contains no private-effort property and **cannot be constructed with public field initialization or deserialized**. Only `TryFrom<&RoleObservation>` produces a serializable view after domain validation, preserving owned commitment summaries. The projection still does **not** replace role-aware authorization; the future service must select the appropriate observation for the requesting role.

## Version and precision rules

- All 64-bit versions carried over JSON are **canonical decimal strings**, including values above JS `Number.MAX_SAFE_INTEGER`. The domain's `WireU64::from_decimal` rejects negative, fractional, leading-zero or over-range strings. No public JS `number` for version/cursor IDs.
- All real financial reservations remain **integer micro-USD**, not floating-point JS values. The app-level spending ledger is a separate P5 concern and is not supplied by this PR.
- Enum variants use snake-case JSON strings; commands and counterproposals use tagged `kind` objects, including checked **empty-struct** variants that reject unexpected properties. First and final minister action shapes are tagged by `stage`. Extra properties are rejected by Serde. The schema and TypeScript are **generated by Rust**, not copied UI model definitions.

Regenerate and check:

```sh
cargo +1.99.1 run --locked -p myth-contracts --bin export-contracts -- --write
cargo +1.99.1 run --locked -p myth-contracts --bin export-contracts -- --check
cargo +1.99.1 test --locked --workspace
npm --prefix apps/web ci --ignore-scripts
npm --prefix apps/web run build
```

Routine CI uses **`--check`**, runs `cargo fetch --locked` to enforce the committed dependency graph (without cache-dependent lockfile regeneration), runs Rust formatting/lints/tests, and builds the frontend. A generated-file mismatch fails the PR. No paid model calls occur.

## Important remaining gates

- **Schema constraints are not exhaustive**: `schemars` emits canonical decimal-string patterns and numeric bounds; the Rust converter remains authoritative for `u64` overflow (e.g. a 20-digit value above `u64::MAX`), exact identifiers, sanitization, conditional stage/role rules, total allocations, and full domain invariants. Generated TypeScript still represents most bounded integers as `number` and cannot enforce numerical limits alone. A schema-valid input is not necessarily admissible.
- **Selected LLM response-format subset is NOT certified yet.** The emitted JSON Schema is schemars's general schema; provider support for `$defs`, discriminated unions, nested required fields, nullability and `additionalProperties` has not been tested. Before any OpenRouter request, P5 must freeze one model/provider route and verify/restrict schema to that route's supported strict subset. Do not imply a `response_format` integration exists.
- Domain-owned validation now covers funded-condition construction, IDs and public rationales. It rejects ASCII controls and known Unicode bidi/zero-width formatting characters. This does **not** constitute HTML escaping or prompt-injection defense; render rationales as text and do not treat them as instructions. The P3 reducer must validate every state entry point.
- LF line endings are enforced for generated contract files in `.gitattributes` to avoid false drift on Windows; actual second-OS replay remains outstanding.
- The P1 world/event/ledger/receipt *types* and strictly checked private checkpoint now exist (see `docs/p1-operating-contract.md`). P2 still must provide reviewed evidence packs; P3 must authorize transitions and P4 must implement durable replay. The P1-03 provider-selected strict structured-output subset remains **unverified** until P5 chooses and tests an approved route. P1-04 needs an offline Axum service with role-scoped server-side commands and save/restore. P3 must implement full command admission, member organizations, enforceable conditions and the shared-family schedule. P4 is the Hiyal adapter.
- P1d has removed the duplicated `apps/web/src/game.ts` best-case calculation and now calls a Rust-domain optimistic capacity preview through the loopback Axum adapter. This is still not a P3 authoritative world/treasury reducer; TypeScript only renders its validated response.
- Organization interests and contextual warnings are public; first-playable exact authored trigger rules should be inspectable on request. Private minister effort and unobserved preferences must remain private. The current preview's exact trigger copy is a UX follow-up, not authorization to reveal private agent state.
- No cross-platform replay, user-data ingestion, invoice verification, API key loading or real policy outcomes have been verified here.
