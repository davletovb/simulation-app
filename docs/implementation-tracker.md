This tracker turns those discussions into work and gates without editing the reviewed framework. Public hosting is not a prerequisite for the first playable.

## Tracking rules

Check an item only after its acceptance conditions are met. Record the implementation commit and relevant test output, report, or manual result in the evidence log below; distinguish executed checks from code or documentation that was only written. Document a blocker rather than checking a partial task. Stable IDs can be referenced in commits and later issues; split a large item into suffixes if needed and retain its original acceptance conditions.

Phases are dependency gates, not calendar estimates. Small preparatory tasks can overlap, but do not proceed past a failed gate or silently change a model assumption to make a test pass. Live calls always obey the README's operating policy.

## First-playable target

Use one reviewed real-country snapshot with approximately 6–10 indicators and visible gaps; fictional finance, education, and infrastructure ministers; six weighted population cells; two rule-driven organized interests; one narrative overlay; and six quarterly decisions. The education-reform case must include conditional agreements, delivery and audits, and remembered commitments. Define three small policy families within that case, with at least two feasible resolutions that lead to different, explainable tradeoffs.

Near-term outcomes concern funded activity, staffing, access, capacity, and delivery. Longer-term learning or growth remains an explicitly uncertain projection unless a justified mechanism supports an earlier effect. Country selection, exact mechanisms, institutional rules, model, locales, and numeric resource targets are still open tasks.

- [x] **P0-01 — Country and evidence boundary.** Select the first country and cutoff after a small data-feasibility check. - [x] **P0-02 — Case contract.** Specify the simplified institution, each actor's authority and leverage, approval/override rules, quarterly time step, two-round meeting boundary, and the three supported policy families. Define one education-delivery mechanism, its units, lags, constraints, and evidence or authored parameter basis. Specify the cohort response channels and each organization's membership, resources, decision rule, and consequential action, with functional forms, units, lags, coefficient sources, and initial sensitivity ranges for P3-07.
- [x] **P0-03 — Decision and information contract.** Define proposals, amendments, enforceable versus political commitments, capacity choices, audits, and permitted observations. Decide whether proposals start only from the typed builder or also from parsed free text; any parsing call counts toward P0-04's allowance, and its result stays a draft until the player confirms it. Keep chat/speeches outside minister decision inputs. Specify the single evidence type and adjustable belief, with relevance, conflict, magnitude, and duplicate-use rules, plus a total update budget so distinct evidence items cannot ratchet the belief indefinitely.
- [x] **P0-04 — Targets and inference allowance.** Declare numeric call, input/output/reasoning-token, repair/retry, and cost allowances for a period, campaign, and evaluation batch. Size caps in the units Hiyal actually reserves: at the pinned revision, [`GovernedBackend`](https://github.com/davletovb/hiyal/blob/050d1de094f5d0813817e2020ec5c5da97d5c42e/src/guard.rs#L30-L66) charges every dispatched call its upper bound (serialized request bytes at the input-token price plus the full `max_output_tokens` at the output price) and never settles it to reported usage. Its budget configuration has no separate reasoning term, so bound reasoning within `max_output_tokens` or disable it for each route. Define the shared application allowance's identity, scope, reset triggers/epochs, and treatment of unresolved reservations; a process restart or campaign switch must not create fresh allowance. Apply resets and price changes to the shared ledger, never to an existing trial's saved Hiyal budget configuration, which resume rejects if it changes. Set latency, commit, restore, verification, memory, and disk targets, and the P4-05 stress-world size, before measuring. The lean planning count is eight calls per period or 48 per campaign before extras; it is not a provider quote or an all-inclusive cap.
- [x] **P0-05 — Comparison protocol.** Define the independent profile-only baseline, scoring features and weights, reservation behavior, finite candidate menu, and tie-breaker. Define A′'s concession/anchoring measures and adoption thresholds before its first pilot. Declare Experiment A's behavior criteria for accepting a model/route, using the framework's Section 17.3 failure measures: invalid actions after the bounded repair, refusal/hedge rate, contradicted stances and forgotten promises, infeasible agreements, resistance to injected instructions, and private information leaked directly or through repeated probes. Record which model/provider settings, observations, menus, prompts, locale, and shocks are fixed or intentionally varied.

**Gate:** The case has declared variables, units, authorities, response rules, information boundaries, and testable success conditions. Targets and live-call allowances have concrete values before execution. No country, model, or performance result is implied by this tracker.

### P3 — prove the pure rules with scripted actors

- [ ] **P3-01 — Financial lifecycle.** Implement affordability, approved borrowing if in scope, future staffing/maintenance obligations, tranche conditions, and exact stock/flow accounting. Recording a promise or ratification does not automatically disburse cash. Costs and upkeep apply exactly once.
- [ ] **P3-02 — Phases and time.** Implement proposal registration, frozen first positions, bounded amendments, frozen final positions/votes, ratification, and explicit period advance. Advance due spending, delivery, shocks, public responses, relationships, and observations in a declared order; bargaining must not accidentally consume a quarter.
- [ ] **P3-03 — Institutions and commitments.** Enforce authority, capacity, funding, proposal versions, and conditions. Implement the commitment registry, deadlines, and consequences of honored/broken promises. Institutional invalidity is separate from a permitted but politically poor choice; utility gating is not the default.
- [ ] **P3-04 — Society and organizations.** Implement the six rule-driven cells and two organizations, including at least one organization action with a modeled consequence. Reconcile money and population across levels, use declared lags, and feed outcomes into the next meeting's constituency pressure through explicit rules.
- [ ] **P3-05 — Views, previews, and audits.** Build role-specific observations and player previews from permitted information. Keep true effort/losses/private commitments separate from reports. Implement the small audit and evidence-to-belief mechanisms from P0, including repeated/conflicting evidence checks.
- [ ] **P3-06 — Baseline and invariants.** Implement the independent deterministic profile-only selector and scripted cases. Verify accounting, delay/order rules, invalid/stale actions, failed votes, exact rounding/overflow behavior, information visibility, and at least two feasible tradeoffs plus an unaffordable proposal. Reconcile mechanical receipts against state differences.
- [ ] **P3-07 — Offline society sensitivity.** Declare a small sweep over uncertain response coefficients, delivery/response delays, and the unsupported population associations identified in P2-03. Document the evidence or authored basis for parameter ranges and admissible alternative joint constructions before running it. Compare the same policy packages over the playable horizon with actor actions and the per-period exogenous shock schedule fixed across variants; do not re-optimize actions or query an LLM. Recheck feasibility and record infeasible variants rather than silently dropping them. Preserve observed population constraints and accounting invariants. Save the variant definitions, pinned inputs/rules, outcome contrasts, and a concise report identifying assumptions that reverse apparent policy rankings or group-level gains/losses on declared metrics. Report no reversal if none occurs, with the tested range and its limits; this is model sensitivity, not empirical validation.

**Gate — Experiment B:** Headless scripted cases are deterministic and explainable, accounts reconcile, and invalid actions cannot mutate state. Commitments bind from the authoritative registry alone; P5-04 tests that prompt-memory eviction cannot remove them. The offline sensitivity report identifies conditional or reversed tradeoffs instead of treating the baseline assumptions as settled facts; a reversal is a finding to disclose, not a failed software invariant. No LLM, network, or Hiyal dependency enters the pure reducer.

- [ ] **P4-01 — One game world.** Wrap the pure rules in the game-owned Hiyal `World`. Use cabinet actors and one period-advance actor; keep rule-driven cohorts inside world records. Maintain one writer per trial and keep full transcripts/trajectories outside mutable world state.
- [ ] **P4-02 — Execution phases.** Map eligible actors to audited pause/resume operations and frozen rounds. Preserve deterministic commit order and separate logical actions from calendar time. Use sequential steps for named policy RNG until a supported round RNG contract is verified.

Implement the allowlisted, side-effect-free `player_command` effect with command body, ID, expected version, and stable operation ID. Preserve enough durable association to reconstruct pending work for P6's service.
- [ ] **P4-04 — Durability and replay.** Start with `EveryEvent`, verified checkpoints, normal full validation, resume, and strict recorded-action replay without dispatch. Test interruption between effect receipt and action, and during a frozen round. Reuse durable receipts; retain unknown billing when a remote response might have been charged before saving. Do not claim exactly-once remote billing.
- [ ] **P4-05 — Small B′ check.** Measure prototype-size and the small stress world declared in P0-04 for cabinet/period commit time, checkpoint size, restore/full verification, memory, and disk. - [ ] **P4-06 — Adoption decision.** Record which A–C/B′ requirements the adapter meets and any generic engine gaps. Retain Hiyal provisionally only with evidence; keep corrective engine work separate from game mechanisms and preserve the replaceable rules boundary.

**Gate:** Saved scripted runs restore and replay to identical authoritative hashes on each operating system declared in P1-01, without network access. Recovery evidence and small-world resource measurements meet P0's declared targets. An adapter gap is recorded before proceeding; this phase alone does not establish the live cabinet or final engine adoption.

### P5 — add the OpenRouter cabinet

- [ ] **P5-01 — Schema-capable backend.** Implement and test an OpenRouter-only Hiyal backend. Require supported structured-output parameters, verify each action schema, and record actual model/provider identity and request settings. Pin routes/settings for controlled comparisons; reject unapproved route/model fallbacks. Any bounded JSON-text fallback and repair stays on OpenRouter.
- [ ] **P5-02 — Admission and accounting.** Wrap calls with `GovernedBackend` and one authoritative shared local application allowance covering every campaign plus assistant/authoring calls outside trials. At the pinned revision, [`GovernedBackend` recovery](https://github.com/davletovb/hiyal/blob/050d1de094f5d0813817e2020ec5c5da97d5c42e/src/guard.rs#L265-L317) is per trial: opening or resuming a trial replaces the process-local remaining amount with that trial's receipt-derived usage, calls outside trials or in flight at a crash leave no receipts to recover, and resume rejects a changed budget or price configuration. Use one instance per trial with a fixed configuration, behind a game-owned durable ledger that alone holds the shared allowance; never share one instance across campaigns. Atomically persist reservations with stable call/reservation identities before dispatch; recover both trial reservations and the overall application allowance before permitting new calls after restart, without double-counting recorded calls. Keep this durable accounting separate from rebuildable views; fail closed if it cannot be recovered. Implement P0-04's explicit reset rules and retain unresolved reservations across reset boundaries. Uncertain charges remain reserved until verified reconciliation; restarting or switching campaigns must not replenish the allowance. Bound concurrency, request/output/reasoning sizes, repairs/retries, and estimated spend. Distinguish reserved capacity, reported usage, estimates, verified charges when available, and unknown billing; state which amounts the shared ledger releases when usage is reported, since the per-trial cap never releases them. Do not present this local contract as a distributed wallet or exact provider invoice.
- [ ] **P5-03 — Ministers and memory.** Add three distinct profiles with role-visible typed observations, persistent agreements, bounded context, and independent first positions. Support amendments, conditions, final positions/votes, and authorized effort choices. Keep speeches/chat out of decision inputs and classify timeout/parse failures as operational failures, with an explicit visible retry or labeled fallback.
- [ ] **P5-04 — Cheap verification first.** Use captured or fake HTTP responses for malformed/schema-invalid output, missing usage, errors, cancellation, quota/budget exhaustion, and partial streams. Check that no key reaches receipts, prompts, or captured fixtures (redact captures before committing them), that failures do not fabricate support, and that an exhausted allowance pauses new inference. Put injected instructions in player text, news, and evidence fixtures, and verify they cannot change a minister's role, authority, or permitted actions. Evict agreement entries from bounded prompt memory and verify the registry still enforces them and later observations still include them. Add a process-restart test with at least two campaigns plus assistant and authoring calls outside trials: interrupt around reservation, dispatch, and receipt persistence; verify recovery against durable reservation/settlement records, in either campaign opening order, without replenishing the allowance, double-reserving recorded calls, or refunding uncertain charges. Test declared resets with unresolved reservations carried forward and rejection of new dispatch when durable allowance recovery fails. These checks use no live inference.
- [ ] **P5-05 — Capped live Experiment A.** Run a small, manually triggered cabinet evaluation within P0's allowance, using one model across ministers. Compare against the deterministic baseline. Record whether concessions/constraints change typed actions and implementation, with latency, tokens, invalid responses, P0-05's failure measures, and failure cases; change the action space if the LLM changes only dialogue. Strictly replay the recorded live run offline, without an API key, to identical authoritative hashes.

**Gate — Experiment A:** At least one genuine disagreement changes a permitted action path, agreements persist through prompt-memory eviction, invalid responses are handled correctly, and the recorded live run replays offline to identical authoritative hashes. The chosen model/route meets P0-05's behavior criteria and the declared schema, latency, and allowance criteria. Offline restart evidence demonstrates recovery of the shared allowance across campaigns and out-of-trial calls, including retained uncertain charges and explicit reset behavior; routine checks still work offline.

### P6 — connect the local service and minimal interface

- [ ] **P6-01 — Durable command API.** Add Axum command/status endpoints and one owning task per live trial. Deduplicate by campaign/command ID and normalized payload; return an existing operation/result for identical retries, reject ID reuse with changed content, and check expected versions on new application. Return `202 Accepted` only after durable acceptance and recovery association, independently of the original HTTP connection.
- [ ] **P6-02 — Recoverable SSE.** Publish role-visible snapshots/updates with trial identity, committed cursor, and view version. Capture each snapshot, its cursor, and its view version from the same verified committed boundary, both on initial loading and snapshot fallback; never pair an older snapshot with a cursor read after a later commit. Join catch-up to live delivery without a gap; handle `Last-Event-ID`, duplicates/older versions, cursor gaps, and snapshot fallback. Keep provisional generation progress separate from committed state and explicitly enable keep-alives. Wire TanStack Query to these server views without interpreting raw simulation rules in TypeScript.
- [ ] **P6-03 — Local player surface.** Serve the built React interface and API from one loopback origin, with Vite proxying during development. Build briefing/evidence, typed proposal, cabinet/amendment, and outcome views. Use selective re-themed Tailwind/shadcn/Base UI components, explicit application locales, and safe exact budget-entry contracts. Include inspectable assumptions and pending/failure states.
- [ ] **P6-04 — Connected decision.** Wire briefing → proposal/preview → positions → player amendment → final decision → quarterly consequences → durable save → report. Demonstrate reload, strict replay, and a fork from a verified committed decision boundary. Preserve the same declared exogenous shock schedule where comparisons require it.
- [ ] **P6-05 — Fault and cost checks.** Test lost HTTP acknowledgments, identical retries and changed-payload ID reuse after a restart rebuilds the command lookup, receipt-before-action crashes, mid-round restart, forced SSE disconnects, duplicate/out-of-order updates, visibility leaks, cross-campaign isolation of commands/streams/saves, exact numeric round trips, and a late report. For both initial loading and snapshot fallback, force a concurrent commit during snapshot/cursor capture and stream attachment; verify a consistent snapshot/cursor/version pair and that the intervening update is represented by the snapshot or delivered in its subsequent stream, without a skipped transition or duplicate application. Check that recorded replay uses no API key, every live LLM request uses OpenRouter, and no paid infrastructure is needed.
- [ ] **P6-06 — C′ evidence and decision.** Run the connected slice with a small capped live evaluation after offline fault checks. Record waiting time, invalid actions, preview/commit/restore/full-verification metrics, and separate usage/billing categories against P0 targets. Record pass/fail and any revision before freezing implementation choices.

**Gate — Experiment C′ (including C):** One complete connected decision survives the specified interruptions, saves and replays correctly, and visibly connects bargaining to material consequences. Retries never apply a command twice, including after restart, and campaigns stay isolated. Concurrent-commit checks demonstrate same-boundary snapshot/cursor recovery for initial loading and fallback. Cost and resource evidence meets the declared limits. No hosting deployment or full large-population benchmark is required for this gate.
